## 2. 时钟树配置与验证
**日期**：2026年9月21日

**功能描述**：配置系统时钟，使 STM32F103C8T6 运行在最高性能状态（72MHz）。

**开发历程**：
- **时钟源选型**：芯片支持内部 RC 振荡器（HSI，8MHz）和外部晶振（HSE，8MHz）两种时钟源。查阅数据手册后发现，内部 HSI 精度较差（受温度和电压影响会漂移），且作为 PLL 输入时最高只能到 64MHz，无法稳定达到 72MHz。外部晶振精度高、频率稳定，可以可靠倍频至 72MHz。因此选择 HSE 作为时钟源。
- **配置过程**：在 CubeMX 的 Clock Configuration 中，直接填写 HCLK=72MHz，CubeMX 自动将 PLL 倍频设为 ×9，AHB 分频 /1，APB1 分频 /2，APB2 分频 /1。
- **安全性验证**：针对自动生成的连带改动，对照数据手册进行了安全性验证。确认 APB1 实际频率为 36MHz（符合 36MHz 上限规定），APB2 实际频率为 72MHz，各项参数均在 STM32F103 规范内，无超频或违规风险，可安全使用。

**功能描述**：控制板载 LED（PC13）闪烁，验证编译与烧录链路是否通畅。

**开发历程**：
- **引脚选择**：查阅 DS5319 数据手册 Table 5，选择 PC13 作为输出引脚（该引脚核心板默认接了 LED）。

- **资源评估**：编译通过，生成 `.elf` 文件。终端显示 Flash 占用 4.7KB，RAM 占用 1.5KB。极低的资源占用为后续添加电机、PS2、舵机代码留出了极其充足的 64KB 空间。

## 5. 硬件连接与首次烧录（点灯成功）
**日期**：2026年9月24日

**功能描述**：连接 ST-Link 与 STM32 核心板，完成首次烧录，实现板载 LED 闪烁。

**开发历程**：
- **硬件到货与检查**：收到 ST-Link V2 仿真器与 STM32F103C8T6 核心板。确认 ST-Link 接口为 Mini-USB，核心板排针焊接完好。
- **驱动确认**：将 ST-Link 插入电脑，设备管理器“通用串行总线设备”中识别到 `STM32 STLink`，确认 CubeIDE 安装时已自动完成驱动部署，无需手动安装 STSW-LINK009。
- **接线方案**：采用 SWD 模式，仅需 4 根杜邦线。对应关系为：ST-Link 的 `3.3V`→核心板 `3.3V`、`GND`→`GND`、`SWDIO`→`SWIO`（核心板丝印简写）、`SWCLK`→`SWCLK`。接线时确保杜邦线插紧，避免接触不良。
- **烧录过程**：打开 CubeIDE 的 `crtc_led` 工程，点击 Run 进行烧录。过程中弹出 ST-Link 固件升级提示（显示固件版本 Unknown），因使用的是兼容版 ST-Link，选择关闭该窗口不进行升级，避免变砖风险。
- **点灯结果**：烧录完成后，控制台显示烧录成功、无错误。核心板上的 PC13 LED 以 1Hz 频率闪烁（每 500ms 翻转一次，亮灭各 500ms），首次硬件链路验证通过。

**经验总结**：硬件链路已打通，软件环境与驱动均正常。核心板上的 `SWIO` 即 `SWDIO` 的简写，两者功能一致。兼容版 ST-Link 遇到固件升级提示时，在不影响烧录的前提下应优先选择跳过。


## 6. 电机驱动调试（DRV8833 + TIM2 PWM）
**日期**：2026年9月26日

**功能描述**：配置 TIM2 四路 PWM，通过 DRV8833 驱动 TT 马达，验证正反转与调速功能。

**开发历程**：
- **引脚分配**：在 CubeMX 中配置 TIM2 四通道 PWM（PA0-PA3），并选用 PB3-PB6 作为方向控制引脚。原计划使用 PB0-PB3，但发现 PB2 在核心板上被 BOOT1 占用未引出，改用 PB3-PB6。
- **调试接口选择**：PB3、PB4 默认是 JTAG 调试引脚。在 SYS 中选择 Serial Wire（SWD）模式后，JTAG 被关闭，PB3、PB4 被释放为普通 GPIO，可正常用作方向控制。烧录仍使用 PA13（SWDIO）、PA14（SWCLK），不受影响。
- **代码实现**：编写 `Motor_SetSpeed(uint8_t motor_id, int16_t speed)` 函数，根据电机编号映射对应的 PWM 通道和方向引脚，实现正反转与限幅保护（±1000）。
- **关键踩坑——STBY 引脚**：DRV8833 接线全部正确（AIN1/AIN2 接 STM32 信号，VM 接电池，AO1/AO2 接电机，共地），但电机完全不转。逐项排查电池、电机本体、排针、接线后，发现 DRV8833 模块上有一个 `STBY` 引脚，悬空时芯片处于待机状态，所有输出关闭。将 `STBY` 接 3.3V 后，电机立即正常转动。
- **测试结果**：电机能正常正反转、调速（PWM 占空比 30%），DRV8833 通道验证通过。四个电机未全部联调，麦轮底盘尚未组装。

**经验总结**：DRV8833 的 `STBY` 必须拉高（接 3.3V），否则芯片不工作。这是一条数据手册里容易忽略、但实操中非常致命的细节。另外，核心板上的 `PB2` 通常不引出，方向控制引脚需避开。


## 7. PS2 手柄调试（软件 SPI 通信与电机控制）
**日期**：2026年9月27日

**功能描述**：通过 PS2 无线手柄接收器与 STM32 通信，实现手柄按键读取与电机控制。

**开发历程**：
- **通信方案选型**：最初尝试硬件 SPI（PA4=CS、PA5=SCK、PA6=MISO、PA7=MOSI），CubeMX 中 SPI1 配置为 Full-Duplex Master、LSB First、CPOL Low、CPHA 1 Edge、Prescaler 256。但烧录后 PC13 始终表示收到的 `PS2_Data[1]` 低 4 位为 `0xF`（即 0xFF），说明接收器未驱动 MISO 线，通信失败。多次排查接线、确认参数后未解决。
- **改用软件 SPI**：关闭硬件 SPI，将 PA4 设为输入（DAT），PA5/PA6/PA7 设为输出（CMD/CS/CLK），手动翻转 GPIO 模拟 SPI 时序。软件 SPI 时钟频率远低于硬件 SPI，接收器响应正常。
- **关键踩坑——MODE 键**：通信建立后，PC13 闪烁次数表示手柄返回的 ID 字节。初始返回 `0x41`（数字手柄模式，闪 1 下），通信正常但功能受限。按下手柄 MODE 键切换至模拟红灯模式后，返回 `0x73`（闪 3 下），可读取全部按键与摇杆数据。
- **按键验证**：改写主循环，判断 `PS2_Data[3]` 的 0x10 位（UP 键）。按住 UP 键，PC13 灯亮；松开，灯灭。验证通过。
- **电机控制**：将 UP 键映射至 `Motor_SetSpeed(1, 500)`。按住 UP，电机1正转；松开，停止。PS2 控电机链路打通。
- **延迟优化**：软件 SPI 中每次位传输使用 `HAL_Delay(1)`，9 字节传输总延迟约 144ms，操作手感明显滞后。将 `HAL_Delay(1)` 替换为空循环 `for (volatile int d = 0; d < 50; d++)`，延迟降至微秒级，操作手感明显改善。主循环中的 `HAL_Delay(50)` 同步降至 10ms。
- **排查接触不良**：调试过程中电机突然停转，重启后无效。排查电池、电机本体、线路后确认均正常，最终发现 DRV8833 的 STBY 杜邦线松动导致芯片进入待机状态。重新插紧后恢复正常。

**经验总结**：
- 硬件 SPI 虽然理论速率更高，但对 PS2 接收器的低速响应不一定兼容；软件 SPI 时序可控、速率可调，在本场景中反而更稳定。
- PS2 手柄的 MODE 键是功能开关，未切换至模拟红灯模式时只能读到基础按键，无法使用摇杆数据。
- 杜邦线缠绕式连接在调试中容易因震动或插拔导致接触不良，表现出的症状与硬件损坏类似（如突然停转）。遇到此类问题应先排查接触，而非直接判定模块损坏。
- 最终采用软件 SPI + 空循环延时方案，通信稳定、延迟可接受，暂不切换至硬件 SPI。

## 10. 四电机联调与麦轮运动学修正
**日期**：2026年10月11日

**功能描述**：完成四个电机与麦轮底盘的联合调试，修正运动学公式，解决上电乱转与方向错误问题。

**开发历程**：
- **上电乱转**：不连手柄上电，四个轮子出现“两个快、一个慢、一个不转”的异常。排查后确认是PS2无效数据（未配对时ID为0x00/0xFF）被当成摇杆值算入麦轮公式。在`PS2_Read`中加入ID有效性检查，只接受模拟红灯（0x73）和模拟绿灯（0x53），无效时将按键置0xFF、摇杆置0x80，电机立即停转。同时放弃数字模式（0x41），因为其无摇杆数据。
- **前后方向整体反**：四个轮子前进时全部反转。先尝试改代码翻转方向引脚逻辑，后直接对调电机线，前后恢复正常。
- **左右方向反**：对调电机线后，左右平移方向反了。将`vy`取负号（`int16_t vy = -joy_lr * 1000 / 128;`），左右恢复正常。
- **旋转方向异常**：右旋时左前轮和右后轮转向错误。分析麦轮公式，纯旋转时应该左边两轮同向、右边两轮同向、左右反向。原公式`wheel[0]=vx-vy-omega; wheel[3]=vx-vy+omega;`导致左前和右后omega项符号与预期相反。修正为：
  - `wheel[0] = vx - vy + omega;`（左前）
  - `wheel[1] = vx + vy - omega;`（右前，不变）
  - `wheel[2] = vx + vy + omega;`（左后，不变）
  - `wheel[3] = vx - vy - omega;`（右后）
  修正后旋转方向正确。
- **反转线性度隐患**：DRV8833单PWM+方向脚驱动时，反转平均电压与占空比成反比，速度值越大反转越慢。目前暂未处理，后续若影响手感再改。
- **烧录蜂鸣**：ST-Link连接时即使主电源关闭，STM32仍被ST-Link供电运行，输出PWM导致电机线圈蜂鸣。解决方法：烧录前拔掉电机输出线或DRV8833的VM供电线。
- **接触不良加固**：队友电机线缠绕松散，重新理线，关键点（STBY、VCC、电源、电机输出）用端子或焊接固定，杜邦线插紧后点热熔胶。联调前进行摇线测试。

**经验总结**：
- PS2无效数据是上电乱转的根源，有效性检查必须做，且只认模拟模式。
- 麦轮公式的omega项符号必须与轮子布局匹配，纯旋转时左右两侧反向、同侧同向。
- 方向调试优先改代码，改线会引入新变量，且增加接触不良风险。
- DRV8833反转非线性是硬件特性，若比赛要求精确反转调速，需改用双PWM驱动。
- 烧录时断开负载，避免背电蜂鸣和意外转动。


## 11. 舵机联调：行程限位与上电姿态
**日期**：2026年10月20日

**功能描述**：接入 TIM1 四路 50Hz PWM 驱动四路舵机，确定各关节的实际机械行程，并解决上电瞬间"硬甩"的问题。

**开发历程**：
- **通道与机械对应**：确认 TIM1 四路对应关系为 CH1/PA8 底盘旋转、CH2/PA9 钳子、CH3/PA10 小臂、CH4/PA11 大臂（MG995），前三路为 SG90。脉冲 500~2500µs 线性对应 0~180°。
- **行程实测**：机械组手动转到位后读数，得到各关节机械行程：主干 110~178、底盘 5~135（居中 70）、小臂 29~175、钳子 38（完全闭合）~103（张开合适大小）。据此为每一路建立 `SRV_LO_x / SRV_HI_x` 软件限位。
- **上电姿态踩坑**：最初四个舵机统一上电到 90°，实测发现主干在 90° 时直接顶在机械下限上持续堵转、发出嗡鸣。原因是该关节行程是 110~178，90° 根本不在行程内。改为每关节独立初始角：底盘 70、钳子 103、小臂 135、主干 120，并让 `ang[]` 初值直接引用同一组宏，避免"表和变量对不上"。
- **验证**：上电四个舵机平稳走到各自初始位置并保持；逐路按键到底，角度停在对应限位上，无堵转嗡声。

**经验总结**：
- 上电初始角必须逐个落在该关节的机械行程内，不能统一取 90° 或 180°。
- 限位值和初始化变量不要分开写，用同一组宏。否则改一处忘一处，故障现象会非常难查。

## 12. 疑难故障定位：大舵机"抽搐"与"回归 90°"
**日期**：2026年10月21日

**功能描述**：定位"钳子夹紧时抬升大臂，大臂抽搐甚至失灵、偶尔直接回到 90°"的故障。

**开发历程**：
- **现象**：钳子夹住方块持续按住 × 键时，再按 ↑ 抬大臂，大臂出现两种异常——高频抽搐，或直接"啪"地回到 90° 并保持。底盘与其它舵机表现正常。
- **第一阶段误判——PS2 帧校验**：怀疑无线帧误码，把校验从"只判 ID"改成"ID + 第 3 字节必须为 0x5A"，并加入连续 3 帧失败才判掉线。结果引入新故障：`PS2_Data[]` 上电全为 0，而掉线中性化被推迟到第 3 帧，于是开机瞬间 `data[3]` 的 bit0 被急停逻辑当成"SELECT 被按下"，急停被锁死在 ON，板载灯一直闪、所有舵机冻结。修正为：数组初值直接给 `{0xFF×5, 0x80×4}`，并且急停必须等通信建立（`PS2_Online == 1`）后才开始判边沿。
- **第二阶段误判——指令角饱和**：怀疑 `ang[3]` 一路按到 180° 饱和。实测按 ↓ 同样无反应，排除。
- **第三阶段——供电排查**：观察到"单独控制任何一个舵机都没问题，只有钳子堵转时再抬大臂才发作"，且"只有被驱动的那一路受影响"。调试器上表现为故障瞬间连接断开——说明 MCU 掉电复位。至此确认：**"回归 90°"不是舵机行为，而是 MCU 复位后 `ang[]` 被重新初始化为 90°**。
- **根因**：钳子堵转约 0.7A，大臂启动瞬间 2A 以上，两路峰值叠加把共用 5V 母线拉到 AMS1117 的 dropout 以下，3.3V 塌陷触发欠压复位。

**经验总结**：
- 看到"舵机回到某个固定角度"，先问那个角度是谁的默认值。90° 是软件里 `ang[]` 的初值，不是舵机的默认位——能回到它的路径只有"程序重启"。
- 排查时把"哪几个器件同时受影响"作为判据：共享母线故障会同时影响多个负载，只影响单个关节的故障一定在局部。
- 我在这一阶段加的"防护"（0x5A 校验、3 帧掉线判定、使能门控、轮流让步）在这个故障面前全部无效，反而引入了新 bug。**先定位、后加固**，不要在没定位前堆保护逻辑。

## 13. 机械侧溯源：卡涩、无支撑与舵盘打滑
**日期**：2026年10月22日

**功能描述**：把电控侧的现象追到机械侧，确认过载的真正来源。

**开发历程**：
- **小臂卡涩**：断电后用手转小臂关节，全程"一卡一卡"有明显阻力。正常关节应当全程顺滑无阻。判定为装配问题（轴心不共线或连杆别劲），软件无法补偿，只能机械返工。
- **底盘旋转过载**：拆检发现底盘旋转由一颗 SG90（1.8kg·cm）直接驱动，且平台无任何轴承支撑。舵机同时承受整条臂的轴向重量、弯矩和旋转力矩，远超其设计能力。正确做法是平台坐在推力轴承上，舵机只提供旋转力矩。
- **舵盘打滑**：反复堵转后重新测量，发现此前记录的所有角度都发生了平移。原因是扭矩超过舵盘在输出轴花键上的摩擦极限，舵盘滑齿，`ang` 与实际物理位置的对应关系整体改变。
- **处理**：所有限位改为"设在实测端点内侧 2~3°"，让舵机永远走不到端点，从根源上避免顶死和打滑；随后整套行程重新测量一遍并替换代码中的旧值。

**经验总结**：
- 舵机只能输出扭矩，不能承受轴向力和弯矩。凡是"用舵机当轴承"的结构，堵转只是时间问题。
- 反复堵转会让舵盘打滑，导致此前所有角度标定作废。**限位必须设在端点内侧**，而不是正好卡在端点上，否则每顶一次就滑一次，记录永远不稳定。
- 电控能做的只是"把机构限制在它扛得住的范围内"，机构本身的问题必须由机械侧解决。

## 14. 一次失败的尝试：纯软件自动堵转判定
**日期**：2026年10月22日

**功能描述**：尝试用纯软件实现"夹到方块就停"的自动判定，避免钳子过度堵转。

**方案设想**：在按键循环内逐步减小钳子角度，每步采样一次"位置"，如果连续多次采样值相等，即判定已经堵转，然后把角度停在那个值上。

**失败原因**：
- PWM 舵机是**单向器件**：三线接口只有电源、地、信号，信号线上只有脉冲进、没有任何数据出。
- 代码里唯一名为"位置"的量是自己写的 `ang[]`，它每步都在被人为减 1。即使舵机被卡死不动，这个变量依然在变——**用自己的输出观测物理事件，逻辑上不成立**。
- 舵机内部确实有位置反馈（电位器），但闭环完全封装在舵机壳内，只用于驱动内部电机，没有引出到接口。与 PS2 手柄的四线双向协议（有专门的 DAT 回传线）形成对比。

**经验总结**：
- 要把这个环闭合，必须引入**物理量**：电流、母线电压、限位开关，或者换成能回读角度/负载的总线舵机（如 LX-16A、STS3215）。
- 在这类"哑执行器"上做精密作业，只能依靠人眼 + 标定。这不是方法落后，而是器件特性决定的上限。

## 15. 第二次尝试：逆运动学解算与放弃
**日期**：2026年10月23日

**功能描述**：为机械臂实现平面二连杆逆运动学，尝试用摇杆直接控制方块中心的三维位置。

**开发历程**：
- **几何数据**：实测 L1（大臂轴→小臂轴）=75mm、L2（小臂轴→小臂末端连杆）=68mm、d1（大臂轴→桌面）=111mm、h（小臂末端→方块中心，钳子自由下垂时）=71mm；零位为大臂水平 90°、小臂与大臂共线 90°。
- **实现**：编写 `Arm_FK / Arm_IK`，并增加"笛卡尔点动"模式（左摇杆前后左右、↑↓ 升降）。进入该模式时先用正解算从当前姿态反推目标点，避免切换瞬间跳变；目标超出工作空间时冻结在边界，防止目标漂移导致"推摇杆没反应"。
- **问题一（工作空间极窄）**：用实测尺寸仿真整个可达域，发现在台面高度（z=20mm）时末端可达的水平距离 r 只有 122~125mm，仅 3mm 宽。根因是小臂一直顶在下限 29° 上——低处只剩大臂一个自由度，一个自由度只能画出一条弧。
- **问题二（建模前提被推翻）**：模型建立在"钳子自由下垂、方向恒定竖直、h 为常数"之上。实际钳子抬升后会被一根挡杆挡住，方向改为跟随小臂倾斜，h 不再是常数且随姿态变化。模型从常数偏移退化为分段函数加碰撞约束。
- **问题三（解的分支）**：二连杆对同一位置有两组解（肘上/肘下）。最初按"离当前姿态近"选择，推杆到某个位置时两组解的远近互换，机械臂中途换解，末端出现跳变。后改为锁定当前分支、仅在其不可达时切换。

**经验总结**：
- 逆解本身只有几十行，难的是机构：工作空间、关节限位、姿态约束。
- 建模前必须先确认抽象前提成立（这里是"钳子恒定竖直"）。前提一旦是分段或时变的，整个模型都要重做。
- 结论：这套机构不支持笛卡尔控制，"全向解算"投入产出比为负，果断放弃。

## 16. 最终方案：姿态表 + 同步插值的三个宏
**日期**：2026年10月23日

**功能描述**：放弃几何建模，改用"关键姿态记录 + 平滑插值"实现一键夹取、一键放置、一键归位。

**设计思路**：
- 既然机构不支持连续的自由定位，那就只使用**少量已验证可达的姿态**。每个姿态就是一组四个角度，全部由人工手摆、人工抄录，天然保证可达。
- 一个宏 = 若干步；每一步给出四个关节的目标角。**多个关节同时变化时按各自行程比例插值、同进同出**，避免"大臂先到、小臂还在爬"造成的末端扭曲。
- 只改一个关节的步骤等价于单关节动作，正好对应"先降小臂、再合钳子、再抬小臂"这种顺序动作。

**三个宏**：
- **L1 夹取**：待机 → 小臂升到 161 → 钳子合到 50 → 停 400ms → 小臂回 135（约 2.5s）
- **R1 放置并归位**：大臂 178 / 小臂 30 / 底盘 70 同时变化 → 钳子张开 103 → 停 200ms → 大臂 120 / 小臂 135 同时回位（约 5.5s）
- **START 归位**：任何位置 → 一步平滑回到待机 (70, 103, 135, 120)（≤2.1s）。这是"以防万一"的兜底：宏跑到一半出岔子、或手动把臂摆歪了，一键拉回已知状态。

**关键设计**：
- **时序**：夹紧之后插入 400ms 停顿再抬大臂。这是前面过载故障的直接对策——让钳子的堵转电流先进入稳态，避免与大臂启动峰值叠加。
- **中断**：宏运行中按任意方向键立即取消，控制权交回手动，机械臂停在当前位置，不会卡死。
- **速度**：统一 `MACRO_STEP_DIV=2`，即 50°/s，兼顾"不抖"和"不太慢"。
- **一次一个**：宏运行期间按其它宏键无效，避免状态机被打乱。

**经验总结**：
- 当机构精度不足时，"记住几个做成功的姿态"比"建立精确模型"更划算——前者天然包含所有机械误差。
- 多关节联动必须做归一化插值，否则各轴速度不同会让末端走出一条扭曲的轨迹。
- 宏的价值不只是省按键：它能把人手做不稳的**时序**（停 400ms 再抬）固定下来，这才是它真正缓解过载问题的原因。

## 17. 调试工具链踩坑记录
**日期**：2026年10月24日

**功能描述**：整理本次调试中在工具链上踩到的坑，供后续参考。

**开发历程**：
- **调试器供电不足**：ST-Link V2 的 3.3V 输出仅约 100mA，核心板加 PS2 接收机已接近上限，舵机绝对不能从它取电。正确接法是只接 SWDIO / SWCLK / GND 三根线，板子由电池供电，3.3V 那根不接——两路电源并联会互相倒灌。
- **实时表达式**：CubeIDE 中文包把 Live Expressions 译为"现场表达式"，且该视图**只在调试会话中存在**，没进调试时在"显示视图"里根本搜不到。
- **断点不能下在控制循环里**：`Servo_Control()` 每 10ms 调用一次，断点会让程序每 10ms 停一次，完全无法操作。读实时值只能靠实时表达式或外设寄存器（SFRs，可读 TIM1 的 CCR1~CCR4 直接得到脉宽微秒数）。
- **变量要能被观察**：写在函数内的 `static` 局部变量优化后可能读不到、名字也会被改写。把 `ang[4]` 提到文件作用域并加 `volatile` 后，直接在实时表达式里输 `ang[1]` 即可。
- **中文注释编码事故**：用命令行脚本批量改 `main.c` 时，脚本按 GBK 解码了 UTF-8 的中文注释再以 UTF-8 存回，导致全部注释双重编码乱码、部分字符彻底丢失。后续把源文件注释统一改为 ASCII 英文，彻底规避该问题。

**经验总结**：工具链的坑往往比算法更耗时间。凡是要动源文件的批量操作，一律用支持 UTF-8 的编辑器，不要用命令行脚本做字符串替换。

## 18. 后续计划
- **电源加固（最高优先级）**：目前钳子堵转 + 大臂启动仍会拉塌共用 5V 母线。最便宜的三步：舵机母线并 1000µF/16V 电解、舵机电源线换粗或两根并联、大臂单独供电。不加这条，宏跑多了仍可能复位。
- **小臂关节返工**：断电手转一卡一卡，属装配问题（轴心不共线或连杆别劲），软件无法补偿。返工前只能用限位避开卡涩区间。
- **底盘旋转加轴承**：目前 SG90 直接扛整条臂，应改为平台坐在推力轴承上、舵机只提供旋转力矩。
- **限位复核**：舵盘打滑后所有角度都会平移，每次机械拆装后必须重新测量一遍行程，并把限位设在实测端点内侧 2~3°。
- **宏参数微调**：400ms 停顿、50°/s 速度、三个宏的姿态表数值，都需要在实际场地上再微调。
- **底盘定位训练**：机械臂的工作空间只在半径约 12~13.5cm 的窄环内，实际操作时要靠底盘把方块送进这个范围，操作手需要练熟。
- **视觉串口对接**：与视觉组确认USART3数据格式（当前为`X:%d,Y:%d,Found:%d`），联调接收稳定性与超时处理。视觉模块可以做"粗定位"，让底盘自动微调对准，不涉及逆运动学。
- **无线继电器**：中期考核后采购并接入电池总正极，验证10m内遥控断电，检录必查。
- **洞洞板焊接**：从杜邦线过渡到9×15cm洞洞板，核心板、DRV8833用排母，电源/电机线直接焊接，信号线排针加固。
- **接触加固**：所有杜邦线插紧后热熔胶固定，STBY/VCC/电源/电机输出优先焊接或端子。
- **备用方案**：准备备用杜邦线、备用DRV8833、备用 SG90（钳子/小臂容易因长期堵转损坏），确认备用机器人接口兼容。
- **检录预演**：尺寸、重量、结构强度（180mm自由落体无零件掉出）、无线断电功能提前自测。
